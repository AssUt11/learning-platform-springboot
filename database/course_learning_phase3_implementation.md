## 3. 后端接口

### 保存课时进度

`PUT /api/learning/lessons/{lessonId}/progress`

- 用户 ID 只从登录态取得。
- 只允许学生或教师学习账号写入；管理员预览不记录进度。
- 只允许公开、审核通过、内容完整课程中的已发布课时。
- 服务端校验课时确实属于请求课程。
- 视频时长优先使用课时库中的权威时长，播放位置被限制在合法范围内。
- 完成状态由服务端按播放位置计算，忽略客户端附加的 `completed=true`。
- 使用幂等 upsert，并通过 `greatest` 防止延迟的旧请求导致进度倒退。

### 获取课程总进度

`GET /api/learning/courses/{courseId}/progress`

- 只汇总当前公开课程的已发布课时。
- 返回总课时数、完成课时数、总进度、学习时长、最近课时和各课时进度。

### 继续学习

`GET /api/learning/resume`

- 返回当前用户最近学习且仍然公开可学的课程与课时。
- 已下架、不完整、章节或课时未发布的记录不会成为继续学习入口。

## 4. 安全与边界验证

- 管理员写入学习进度：HTTP 403。

- 客户端在视频第 5 秒提交 `completed=true`：服务端结果仍为未完成、4%。
- 课时 A 完成后再提交第 10 秒的旧请求：服务端仍保留 105 秒和完成状态。

## 6. 浏览器手工验收

示例课程：资源 ID 21；课时 A ID 20；课时 B ID 21。

- 打开 `/learn/21/20`：显示课时 A，视频地址为 A 的本地上传地址。
- 点击下一节：路由变为 `/learn/21/21`，标题变为课时 B，视频地址变为 B 的本地上传地址；两条地址不同。
- 给课时 B 写入 65 秒后重新进入：页面显示“已从 1:05 继续播放”。
- 浏览器继续播放期间，数据库位置从 65 秒自动增长到 137 秒，验证 12 秒周期保存生效。
- 课程总进度显示 10%，课程卡片、课程详情和“我的学习”一致。
- 从课程详情点击“继续学习”：准确进入 `/learn/21/21`。
