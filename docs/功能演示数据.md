# 平台内功能演示数据

已为本机平台准备独立命名的演示数据。账号、课程、笔记、反馈与预置测验均带有“演示”标识，原有账号和学习记录保持不变。

## 从哪里开始

打开项目登录页，使用本机 [演示账号与逐项操作说明](../.runtime/功能演示账号与操作.md)。该文件包含本次生成的登录密码及实际课程链接，仅保存在本机、未加入版本管理。

| 账号场景 | 示例数据 | 可直接体验 |
| --- | --- | --- |
| 新同学·首次规划 | 没有学习记录或已采用路径 | 兴趣选择、五问学习档案、首次学习规划 |
| 小林·需要复习 | 主课程28%进度，最近4题正确率25%，有笔记、收藏、提问及消息 | 基础复习、个性化出题、课时答疑、继续学习、复习路径、学习报告 |
| 小周·已学完待测试 | 主课程全部课时已完成，整课基础测试尚未提交 | 整课测试开放条件、作答、交卷后解析 |
| 小陈·进阶挑战 | 主课程全部课时完成，基础与巩固测试已通过 | 进阶测试、按稳定表现推荐进阶题 |
| 陈老师·课程工作台 | 拥有全部6门演示课程 | 章节资料管理、课件解析、评价与问题回复、教学统计、审核反馈 |
| 管理员·功能体验 | 独立的演示管理员账号 | 演示课程审核、上下架、社区治理与管理控制台 |

登录页提供“演示学生、演示老师、演示管理”三个入口。点击后会自动填入对应演示账号的邮箱和密码，再走正常登录流程：学生进入学习首页，老师进入课程工作台，管理员进入管理控制台。学生默认使用“小林·需要复习”，其余学习状态仍可使用本机账号说明中的登录信息。

演示管理使用单独创建的管理员账号，原管理员账号与密码不变。管理控制台已有待审核、待修改和已下架课程，可在这些演示课程上体验审核与管理。

## 数据范围

6门演示课程各4章，共50个课时。3门公开课程覆盖基础、中期、进阶；3门非公开课程分别展示待审核、已驳回与已下架状态。视频复用项目中已有的两份本地录播，播放器明确显示临时演示提示；学习知识以配套图文讲义为准。

主课程还提供真实可下载的TXT文件和教师练习。文档已经过平台实际解析、预览与确认，可在课时内AI伴学中检索并打开参考原文。

预置测验与预置对话明确标注“功能演示样例”，使用 `demo-seed` 来源。后来通过平台实际调用本地模型生成的智能练习、课时答疑、独立对话和Word报告，保留真实模型来源，不把预置内容伪装成实时生成。演示进度与成绩只属于演示账号。

私人笔记按演示学生分别保存。预置私信仅在本次新建的演示学生与演示教师之间，不向原有用户发消息。管理员审计记录不预造；实际操作演示课程时，由平台正常记录。

## 初始化与保留

项目依赖就绪并启动后，先预览，再按需添加：

```powershell
node frontend/scripts/seed-feature-demo.mjs
node frontend/scripts/seed-feature-demo.mjs --apply
node frontend/scripts/prepare-demo-login.mjs --apply
```

默认只读预览。首次添加前保存原有记录的校验摘要，课程结构与学习样例在事务中新增；账号通过平台注册接口创建。密码随机生成，保存在 `.runtime/feature-demo-manifest.json`。重复执行会保留已经存在的整套演示数据，不重置演示账号后续的学习与操作。不要删除本机清单后再次初始化；发现同名账号或已存在课程时，脚本会停止，避免覆盖或重复添加。

一键登录初始化只新增命名固定的演示管理员，不修改原账号。它生成本机 `.runtime/demo-login-accounts.json` 和 `.runtime/demo-login.local`，后者使从项目根目录或backend目录启动的本机服务读取演示设置。配置文件与密码均不进入前端包和版本管理。演示入口默认关闭；只有显式准备本机配置后才开启，并限制本机来源，开发代理同时传递原始请求地址。设置 `DEMO_LOGIN_ENABLED=false` 可关闭快捷入口；普通登录、注册保持原流程，公开注册不允许创建管理员。

初始化不会改变模型与站点运行检查。Neo4j离线时，个人路径仍可从MySQL读取，并如实显示待同步状态。
