# 课程编排与自适应学习

更新日期：2026-10-20。

## 模块职责

本轮结合“完善建课与资料上传、体现学生个性化路径”和“AI 辅导教师、智能出题、自适应路径”的要求，复用现有项目模块。

| 模块 | 本轮行为 | 边界 |
| --- | --- | --- |
| 教师工作台 | 创建课程后直接打开目录；作品列表“管理章节与资料”可编排章节、课时、排序、停用及编辑资料 | 教师只能修改自己的课程；改动进入原有管理员审核 |
| 课程学习 | 展示教师讲义、独立视频、文档及补充文档；继续保存课时进度 | 视频使用现有 MP4 播放能力；PPT 通过资料链接打开，无在线转换功能 |
| 课时 AI 辅导 | 复用已有课时答疑，新增课后自测 | 基于该课时文字资料；无讲义或摘要时不能凭空出题 |
| AI 练习 | 调用当前配置的 Ollama / LLaMA-Factory Provider，生成选择题，提交后计分并保存原文依据与解析 | 学习参考，不是教师正式考试；答案仍需结合讲义核对 |
| AI 学伴 | 四类分析读取实际课时进度与最新测验反馈，重新规划参考薄弱课程 | 保留诊断、报告、路径、资源推荐四种任务；独立聊天不承担课程编辑 |
| 个人学习路径 | 每次读取刷新节点进度、自测成绩和下一步建议 | 保留生成的路径快照和先修顺序；不凭测验改写公共知识图谱 |
| Neo4j | 延续现有课程目录自动同步与个人路径同步 | 练习和成绩以 MySQL 为准；图谱不可用时仍读取保存的个人路径 |

## 教师流程

1. 创建课程，填写课程方向、简介及正文。方向列表包含公共分类中的方向及已有课程科目。
2. 在自动打开的目录编辑器中添加章节和课时；也可从作品列表重新打开。
3. 选择课时类型：图文讲义、视频、文档/PPT、教师练习。
4. 图文和练习填写正文；视频上传 MP4；文档上传 PDF、DOC/DOCX、PPT/PPTX、TXT。
5. 文件课时可填写文字摘要，供 AI 答疑和出题使用。系统不会自动提取视频/PPT 的文字。
6. 编辑、排序、资料增删会触发原有待审核状态。管理员审核通过后，学生才能看到更新内容，课程目录由现有同步服务写入 Neo4j。

停用章节或课时保留历史学习记录。练习课时原有教师正文，与下方 AI 生成自测分别呈现。

## 学生流程与反馈规则

在 `/learn/{courseId}/{lessonId}` 阅读资料后，使用“生成课时练习”。模型通常生成一道单选题，解析器接受一至两道完整题目。服务端要求四个不同选项、唯一答案索引、解析及原文依据，依据必须来自当前讲义，正确选项必须出现在该依据中。失败最多修正一次，仍不通过则报错，不保存无效题目。

提交前接口不返回答案、解析或原文依据。提交后由服务端计算得分，显示选择结果、正确答案、解析和引用原文。重复提交返回已有成绩，不能通过修改请求刷改。生成与成绩按登录账号隔离；生成中站内切页不会取消后端任务，返回课时后轮询恢复结果。服务重启会结束尚未保存的生成，已经保存的题目和成绩不受影响。

最近一次已提交测验用于难度选择：未测或低于60分为基础，60–79分为巩固，80分及以上为进阶。题量少，不能当作完整知识掌握评估。

路径读取使用每个课时最近一次已提交测验及 `lesson_progress`：

- 存在低于60分的课时：优先复习该课时。
- 学习完成但尚未测验，或部分测验未达80分：建议自测/巩固。
- 所有课时学习完成且各课时测验都达到80分：该步骤显示“学习已完成”，下一步跳过它。
- 未完成学习：继续首个未完成课时。测验及格不会伪造课程完成记录。
- 已撤回或下架课程：提示重新规划，不提供开始学习按钮。

路径保留原有顺序。需要调整课程组合或学习目标时，在 AI 学伴重新运行路径分析；新分析读取最新学习与测验反馈，并生成新的保存记录。

页面分别显示模型建议的完成标准和平台进阶条件。平台自动反馈依据是“全部课时完成且各课时自测达到80分”，不会因为模型给出的建议阈值不同而更改计分规则。

## 数据与接口

新增表 `ai_practice_sessions`，增量 SQL 见 `database/ai_practice.sql`。启动时自动创建，不修改原用户、课程、学习进度和历史路径数据。

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/practice/courses/{courseId}/lessons/{lessonId}/latest` | 当前账号最近一次练习及生成状态 |
| POST | `/api/practice/courses/{courseId}/lessons/{lessonId}/generate` | 根据课时文字资料生成新题 |
| POST | `/api/practice/{quizId}/submit` | 提交 `{ "answers": [0] }`，选项索引从0开始 |
| GET | `/api/learning/paths/latest` | 原接口，增加动态节点反馈和 `nextAction` |

教师编排继续调用既有 `/api/teacher/courses/...`、`/api/teacher/chapters/...`、`/api/teacher/lessons/...` 接口，不创建第二套课程模型。

## 启动与回退

继续使用原有后端启动方式；接入本机微调模型时启用 `llamafactory` profile，并保持模型 API、MySQL 运行。业务库本轮没有被启动或更换；本机原 MySQL80 服务启动超时问题需另行处理。

回退应用版本即可移除新增入口；保留练习表和历史记录，不执行删除表或业务数据初始化脚本。

## 验证记录

后端和浏览器验证覆盖：题目结构与原文依据校验、提交前答案隐藏、账号隔离、服务端计分、重复提交、无资料拒绝出题、学习进度与成绩分离、路径建议、下架课程，以及教师添加章节/文档课时并上传 PPT。

本机验证结果：

- 后端100项测试：99通过，1项需显式启用的模型测试跳过；构建成功。
- 27项页面回归通过，覆盖新增练习、教师编排，以及原有路径、分析切页、独立对话和课程按钮；最终文案调整后，相关8项用例再次通过。
- 独立 MySQL（3307）与测试后端（8082）：真实创建课程/章节/文档课时、上传下载、审核发布、修改重新待审及跨教师越权检查通过。
- 真实 LLaMA-Factory `zhidu-qwen3-4b-lora`：生成一道有原文依据的题目，单次实测耗时约38秒；服务端计分、重复提交保持成绩、刷新恢复、跨账号404以及低分后优先复习通过。
- 真实 AI 路径重新规划返回“数据库测验与进阶”，执行来源包含 `lesson_progress` 和 `ai_practice_sessions`。
- 打包页面实测显示保存的题目、成绩及原文依据；刷新后恢复，并可进入最新路径；没有前端运行异常。

以上使用独立测试账号和数据，不代表生产业务库已经启动，也不代表所有科目的生成题目都已人工核对。原 MySQL80 服务仍待修复，现有业务数据没有参与本轮写入测试。
