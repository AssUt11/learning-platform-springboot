# 知度课堂运维手册

## 日常检查

- 每日检查前端、后端、MySQL、Neo4j 服务状态。
- 检查 `/api/categories`、管理员站点健康状态和一个视频 Range 请求。
- 检查磁盘剩余空间，上传目录低于 20% 可用空间时告警。
- 检查后端 ERROR、数据库连接失败和连续登录失败日志。

## 备份策略

- MySQL：每日完整备份，保留最近 7 天；每月保留一份，保存 3 个月。
- `backend/uploads`：每日增量备份。
- `backend/reports`：每周归档。
- Neo4j：正式启用后按学校备份平台策略备份数据卷。
- 备份必须保存到与应用服务器不同的磁盘或备份服务器。

每月至少抽查一次备份可读性，每季度执行一次独立数据库和视频目录恢复演练。

## 常见故障

### 8081 端口被占用

只保留一个后端实例。先确认占用进程确实属于知度课堂，再停止旧实例并重新启动受服务管理器控制的实例。

### Neo4j 不可用

页面会在约 2～3 秒内切换为备用图谱，并进入 10 秒冷却，避免重复堆积连接。检查 7687 端口、账号密码和数据库状态，恢复后刷新图谱页面。

### 视频无法播放

检查文件是否存在、上传目录权限、反向代理 Range 头以及浏览器请求是否返回 206。不要直接修改数据库中的视频地址。

### 登录全部失效

确认 `AUTH_TOKEN_SECRET` 是否被更换。密钥变化会让已有登录令牌失效，用户需要重新登录。

## 课程归档

归档课程保持下架，保留课程、章节、课时、学习记录和审计记录。取消归档后仍保持下架，必须补齐内容、重新检查并由管理员恢复上架。

## 安全要求

- 每位管理员使用独立账号。
- 定期更换教师注册码和管理员密码。
- MySQL 后端账号只授权 `learning_platform` 数据库。
- 不通过聊天、邮件或 Git 发送 `.env`、数据库备份和用户数据。
- 操作数据修复、归档和恢复时记录执行人、时间、目标与结果。
