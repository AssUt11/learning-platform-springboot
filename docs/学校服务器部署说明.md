# 知度课堂学校服务器部署说明

## 1. 部署组成

正式环境包含 MySQL 8、Neo4j、Spring Boot 后端、Nginx 前端四个服务。Redis 未被当前业务代码使用，不纳入最终部署。

建议服务器至少提供 4 核 CPU、8 GB 内存和独立数据盘。视频容量按课程规模预留，上传目录、数据库和 Neo4j 数据必须位于持久存储。

## 2. 首次部署

1. 安装 Docker Engine 与 Docker Compose，或使用学校现有容器平台。
2. 在项目根目录复制 `.env.example` 为 `.env`。
3. 替换 `.env` 内所有 `replace-with-...`，并将 `CORS_ALLOWED_ORIGINS` 改为学校正式域名。
4. 执行 `docker compose config --quiet` 检查配置。
5. 执行 `docker compose up --build -d`。
6. 执行 `docker compose ps`，确认 `mysql`、`neo4j`、`backend`、`frontend` 均正常。
7. 打开学校域名并完成管理员登录、课程播放和知识图谱检查。

`.env` 只保存在服务器，不得提交 Git。生产 MySQL 使用 `zhidu_app` 等独立业务账号，后端禁止使用 root。

## 3. 更新发布

发布前必须备份 MySQL、上传目录和报告目录。然后执行：

```powershell
docker compose build
docker compose up -d
docker compose ps
```

更新后检查：

- `GET /api/categories` 返回 200。
- 管理后台显示数据库正常、公开课程问题为 0。
- 视频请求返回 206，并支持拖动进度。
- 图谱显示 `Neo4j 实时数据`；Neo4j 异常时 3 秒内显示备用图谱。

## 4. 反向代理与 HTTPS

正式域名必须启用 HTTPS。Nginx 将 `/api`、`/uploads` 转发到后端 `8081`，其他路径交给前端单页应用。视频代理不得移除 `Range`、`Content-Range` 和 `Accept-Ranges` 请求/响应头。

## 5. 回滚

保留上一版镜像或 JAR、前端构建文件、发布前数据库备份及 `.env`。新版本异常时停止服务，恢复上一版程序和数据库备份，再核验课程、用户、进度与视频文件。
