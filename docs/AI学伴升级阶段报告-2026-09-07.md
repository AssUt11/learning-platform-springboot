# AI 学伴升级阶段报告

报告日期：2026-09-08
项目：知度课堂 learning-platform-springboot
范围：课程诊断、学习分析报告、学习路径分析、学习资源分析。

## 一、当前阶段结论

当前实现已经从“大模型驱动的固定任务工作流”升级为最小工具型 Agent：保留四个产品入口，由同一个学习 Agent 执行器根据任务调用受控工具，取得学习概况、薄弱知识点、可访问资源或 Neo4j 先修关系后继续生成结果。四个入口不是四个独立模型，也暂不属于多智能体协作系统。

阶段二可靠性能力和阶段三工具循环已完成 MVP，但还没有完成生产级闭环。现阶段不包含长期学习计划、用户确认后的计划执行、自动阶段报告、图谱数据治理和完整质量评估。

## 三、升级顺序

| 阶段 | 要解决的问题 | 主要交付物 | 通过条件 |
|---|---|---|---|
| 一：模型工作流 | 四个入口能得到实际模型回答 | 现有四接口、Word 报告、模型调用适配 | 已有实现和历史联调证据；正式运行环境仍需复核 |
| 二：可靠性与证据 | 回答能追溯、资源有效、请求可控 | 结构化输出、来源校验、统一执行保护、回归样例集 | 来源有效，无越权资源，断流与超时可回收 |
| 三：工具型 Agent + Neo4j | 按任务需要补查数据，而非只用固定预取内容 | 工具注册表、受控执行循环、图谱先修关系查询、执行记录 | 工具调用后能继续推理，路径满足已知先修约束 |
| 四：学习计划闭环 | 建议能落为计划并根据学习变化调整 | 学习目标、计划版本、进度反馈、阶段学习报告 | 能解释调整依据，记录可查看及纠正 |
| 五：四类任务协作与评估 | 四类输出共享证据、结论一致 | 统一任务入口、任务依赖调度、质量与性能评估 | 综合任务可完整交付，失败可定位、可重试 |

Neo4j 纳入首次 Agent 能力升级：在阶段二完成必要基础后，与阶段三工具调用一起交付；不推迟到最终协作阶段。

## 四、阶段二：可靠性与证据

本阶段已完成统一 provider 并发容量、单次调用时限和底层异步请求取消；课时问答与四张卡片共用用户级限流。四张卡片返回请求 ID、提示词版本、工具和来源；`agent_logs` 独立保存 `running/completed/failed`、耗时、错误码、模型、工具、来源和图谱状态。资源候选应用可见、审核、生命周期和内容完整性过滤。当前仍为部分通过：尚未增加结构化结果 Schema、整次多轮任务总时限、跨实例限流和失败原因统计页面。

已完成的实施内容：

1. 按字段与记录条数裁剪输入，保持数据结构完整，统一计算输入预算并预留输出空间。字符预算仅是近似，需结合模型 token 使用量校准。
2. 工具和来源作为结构化元数据返回；正文暂未拆成摘要、发现、建议等独立字段。
3. 候选资源查询应用平台现有的可见性、审核及访问规则；返回资源 ID，后端核验推荐 ID 属于本次可访问候选集合，下载报告使用相同结果。
4. 四卡片与课时问答共用模型并发控制，增加用户限流、总时限、取消和请求 ID。真正终止超时的底层请求，释放执行资源。
5. 已保存任务类型、模型、提示词版本、请求 ID、工具、来源、执行状态、耗时和错误码；后续补统计查询与管理页面。

验收：对四种任务覆盖空记录、长数据、不可见资源、断流和超时；不得输出未授权资源链接，失败结果不得当成成功保存；数据库记录与页面结果能按请求 ID 对齐。耗时指标在本机实测后确定，暂不承诺秒级响应。

阶段报告应列出：已修复项、回归结果、真实响应时间、失败原因分布及遗留问题。

## 五、阶段三：工具型 Agent 与 Neo4j

已完成的实施内容：

- 提供固定工具：查询本人学习概况、查询可访问课程资源、查询薄弱知识点、查询图谱先修关系、校验候选路径。
- 模型选择工具和业务参数，用户身份由后端从登录信息注入，不能由模型自行指定。工具执行固定参数化查询，不接受任意 SQL 或 Cypher。
- 扩展模型消息协议，支持工具声明、调用 ID、工具结果及多轮消息。先验证当前 Ollama/Qwen3 的工具调用行为，再确定适配细节。
- 实现“选择工具 → 执行 → 返回观察 → 继续或结束”的循环。建议初始上限为 4 轮、6 次工具调用，作为待压测调整的配置值。
- 已增加 `PREREQUISITE_OF` / `REQUIRES` 先修关系查询；已有 `CONTAINS` 层级关系不会被冒充为先修关系。课程、课时、知识点完整映射及先修关系数据仍待治理和导入。
- 将图谱同步从普通查询中分离，记录同步版本和来源。图谱为空、不可用或关系成环时，返回明确状态，不能宣称完成了图谱校验。

首个演示任务仍是：学生提出“我想学 Spring Boot，应该先补什么”，Agent 查询学习概况、相关先修知识点及课程资源，给出带来源的学习步骤。代码已支持该调用链；当前本机 Neo4j 未运行且无已验收的先修关系数据，因此完整图谱演示尚未通过。

验收：执行记录能呈现至少一次“工具调用—观察结果—后续决策”；无关工具不会强制全部调用；未知工具、非法参数、越权查询和超过轮数均有明确终止结果；构造的图谱样例中，输出路径符合已知先修关系。MySQL 与图谱结论冲突时说明差异。

阶段报告应包含：实际调用工具、输入与输出摘要、图谱节点及关系来源、路径校验结果、降级样例。仅展示操作摘要，不展示模型内部推理。

## 六、阶段四：学习计划与阶段反馈

实施内容：保存用户确认的学习目标、每周可投入时间、计划步骤与版本；将课程完成、练习反馈、用户纠正关联到计划。播放进度不能直接当作知识掌握率，需明确指标来源。

学习阶段报告包含：统计起止时间、原计划、实际完成、相较上一期的变化、待补知识点、依据及下一阶段建议。样本不足时写明无法判断。生成计划调整草稿后由用户决定是否采用；定时报告属于后续可选功能，本报告不创建自动任务。

验收：同一学生在不同阶段能看到可解释的计划变化；不同用户记录隔离；目标和反馈可纠正；相同时间窗重复生成不会重复累计学习记录。

## 七、阶段五：四类任务协作

保留四张卡片，同时新增综合学习规划入口。由调度服务识别所需任务，课程诊断提供问题依据，学习路径使用诊断与先修信息，资源推荐绑定已验证的路径步骤，报告汇总相同版本的数据。四类任务可共用一个模型，不必部署四个模型。

验收：综合任务能给出一致的诊断、路径、资源与报告；某个子任务失败时明确标记并支持单独重试；整次执行有总预算与终止条件。使用固定样例集与当前单次调用版本比较来源正确率、任务完成率、时延和模型调用次数，再决定是否扩大使用。
