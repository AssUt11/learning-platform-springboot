## 二、验证顺序

1. 记录旧实现的环境和成功请求，留存脱敏依赖树及配置。使用可控测试数据，不依赖某名真实学生的私有记录。
2. 选择明确发布的候选版本，在隔离验证范围内引入核心库与模型适配模块。具体版本不得用未固定的 `LATEST` 或快照替代发布基线。
3. 检查 HTTP 客户端、Jackson、日志、Spring 与 Jakarta 相关依赖冲突，验证编译、启动、请求/响应序列化和基本业务回归。
4. 用普通 Spring Bean 手动装配验证候选组件，不直接向 Boot 2.7 添加面向其他 Boot 主版本的 Starter。
5. 按能力矩阵执行真实模型用例，明确模拟测试与真实模型测试的区别。
6. 对无法通过的项目记录最小失败样例、影响场景和备选路线，再决定版本锁定或升级范围。

记录命令时注明工作目录。建议保存 `java -version`、`mvn -version`、`mvn dependency:tree` 输出；这些命令本次尚未执行，不能记为验证证据。
