## 当前范围

采用 Java 后端内嵌 LangChain4j 的方案，首先验证 Java 17 / Spring Boot 2.7.18 与候选核心库的兼容性。首个业务试点是 `/api/agents/guide` 学习诊断，之后逐步迁移路径、推荐、报告与流式答疑。

本次建立文档结构、任务清单和记录模板。候选依赖未锁定，模型能力、数据库迁移、性能和回退均待实际验证；不把方案描述计为开发完成。

## 文档维护规则

- 总体方案管理目标与范围，任务清单管理实施状态，验证记录管理实际证据。
- 工作项状态使用：待实施、进行中、待验证、通过、未通过、阻塞、暂缓。验证用例开始前统一标为“未执行”。
- 只有完成运行验证并附证据后，才标记“通过”；静态代码存在不代表行为已通过验收。
- “阻塞”必须写明原因、影响与解除条件；“暂缓”必须写明不影响哪些已验收场景。
- 更新记录时填写日期、执行人、代码版本、工作区差异、环境、脱敏输出和结论。
- 新增接口、配置和表字段必须明确标为“拟新增”，实施后再更新为实际契约。
- 文档中的阈值是方案目标；尚无实测值的字段保留“待测”，不填写推测数字。
- 按实际改动更新受影响文档，不覆盖项目其他既有修改或恢复已删除的无关文档。
